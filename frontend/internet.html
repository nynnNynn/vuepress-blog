# 文档目的

这篇文档的目的就是为了在只会在控制台写 js 代码这段时间内对计算机网络，cdn 等概念进行盲人摸象，以混过面试为主，主要信息和理解来源源自 ai，gpt，对于文章博客等情况了解不足

# CDN

# 核心概念

  • 译名为内容分发网络，核心部分是物理上全球分布的各 cdn 服务器缓存内容，搭配一套调度机制
  • 具体使用场景在于使用 cdn 缓存静态资源如图片，样式，脚本代码，react 等开源库，不常变性的内容，另外可以应对 ddos 攻击，即调用全球分布式的大量流量攻击源服务器，可以被 cdn 实施负载均衡并保护原服务器
  • 具体实现方式是通过 dns 解析和缓存机制，使用此种方式优化物理距离，并且有负载均衡机制调度，实现获取资源更迅速
  • 原服务器在全球只存在 1 或几个，唯一能生成真实数据，cdn 服务器只是缓存这部分，并在可用的时候代替原服务器返回这部分内容
  • 不可用的时候触发回源请求向真实服务器请求数据

# 触发流程

  1. 客户端输入 url 走 ip 查询
  2. 本地没命中缓存走 dns 查询，查询本地 dns 缓存
  3. 没查到走上一层权威 dns 查询，智能解析（全局负载均衡在这个阶段发生）
  4. 全局负载均衡策略，cdn 维护了全球 ip 地址表单，根据物理位置查询延迟最低的 ip
  5. 物理位置，负载状况，运营商状况，anycast 自动化
  6. 实现方式为 edns 扩展，让 dns 服务器知道本地真实 ip
  7. cdn 服务器内命中强缓存，如果处在期限内返回资源
  8. 未命中触发回源，一个一般性的实践下，此时发出的 url 和第 1 步中不同，维护应对唯一 ip 地址的源 url 地址
  9. anycast 使用边界网关协议，满足多个物理服务器使用同一 ip
  10. 验证方式，响应头，和 status/size disk cache 命中强缓存，x-cache hit 命中 cdn， x-cache miss 未命中 cdn 需要回源

# 网络安全

# xss

  • 注入代码，使得攻击者的脚本信息在用户浏览器执行
  • 存储型将恶意代码通过表单上传等注入数据库，在被请求数据回返时在用户浏览器执行，常见各种生成内容入口
  • 反射型通过向服务端发送请求引起恶意代码回返，在浏览器执行
  • dom 型通过在 url ，hash 等拼接恶意代码，被浏览器识别执行

处置方法

  • 执行输入过滤，后端对 html 部分进行转译，避免脚本执行，http-only cookie
  • 前端禁用 document.write 等 api，对 url 内容进行转译
  • 使用 csp 配置，基于 http 响应头，禁用内联脚本

csf 配置例子

Content-Security-Policy:
  default-src 'self';
  script-src 'self' https://trusted-cdn.com;
  img-src *;
  frame-ancestors 'none';

http-only cookie

  • 没有啥特殊的，就是把 cookie 通过字段设成 httponly 的，禁止 js 访问
setcookie("sessionid", "abcdef123456", [
    'httponly' => true,
    'secure' => true,  // 建议在 HTTPS 下使用
    'path' => '/'
]);

# CSRF

  • 攻击者利用诱导进入第三方网站，利用 img 标签，发送请求，ajax 等各种能发出请求的手段发送跨站请求，自动携带 cookie 以完成某些涉及 cookie 的操作
  • 处置手段即限制 cookie samesite 的值为 strict(全禁)或 lax(get 允许)post 禁止，检查 origin 头，csrf token（服务端生成随机数带回）， 双 cookie 验证等办法

# 其他高频

  1. 点击劫持
  • 通过透明的 iframe，iframe 允许两个网页在同一上面共存，攻击者可以诱导用户点击执行某种操作
  • 可以通过 http 响应头设置，X-Frame-Options 或者 csp 中的 frame-ancestors 指令
  1. dns 劫持
  • 修改运营商 dns 记录劫持，此项违法，已不多见
  1. http 劫持
  • 因为 http 明文传输，可以修改其内容
  • 使用 https

# OSI 7 层

个人感觉这个要背的话就认栽吧，时间成本得不偿失

内容

  • 物理层 literally 网线硬件
  • 数据链路层 数据封装
  • 网络层 路由，寻址等功能
  • 传输层 点对点数据传输，侧重传输过程
  • 会话层 负责会话管理
  • 表示层 处理数据，确保双端都能理解
  • 应用层 直接提供通信，http 等的快乐老家
